# Запись на звонок

Упрощённый сервис бронирования времени по мотивам [Cal.com](https://cal.com).
Владелец календаря создаёт типы встреч, гость выбирает свободный слот и записывается на звонок.

## Роли

- **Владелец.** Один, задан заранее. Авторизации нет.
- **Гость.** Заходит без регистрации.

## Сценарий

### 1. Владелец создаёт тип встречи

1. Открывает панель владельца.
2. Создаёт тип встречи: название, описание, длительность в минутах (например, «Консультация», 30 минут).
3. Видит новый тип в списке своих типов встреч.

### 2. Гость записывается

1. Открывает главную страницу и видит профиль владельца и каталог типов встреч (название, длительность).
2. Выбирает тип встречи.
3. Видит календарь на ближайшие 14 дней. Дни со свободными слотами доступны для выбора, остальные неактивны.
4. Выбирает день. Справа появляется список свободных времён (например, 16:00, 16:30).
5. Выбирает время и попадает на форму записи.
6. Форма записи:
   - слева сводка: владелец, тип встречи, дата и время, длительность, часовой пояс;
   - справа поля: **имя** (обязательное), **email** (обязательное), **комментарий** (необязательное);
   - кнопки «Назад» (к выбору времени) и «Подтвердить».
7. Нажимает «Подтвердить» и видит страницу с подтверждением: на какую встречу записан и когда.

### 3. Владелец видит запись

1. Открывает список предстоящих встреч.
2. Видит там новую запись: тип встречи, дата и время, имя и email гостя, комментарий.
3. В списке собраны встречи всех типов, отсортированные по времени.

## Правила бронирования

- Окно записи: 14 календарных дней, сдвигается со временем.
- Длительность слота равна длительности выбранного типа встречи.
- Одно и то же время нельзя занять дважды, даже разными типами встреч. Пересечение интервалов запрещено, включая частичное наложение.
- Следующая встреча может начинаться в момент окончания предыдущей.
- Правила действуют и при двух одновременных запросах на одно время.

## Чего в приложении нет

- Авторизации и личных кабинетов.
- Интеграций с внешними календарями.
- Уведомлений.
- Видеосвязи (в Cal.com есть Cal Video, у нас нет).
- Приглашения дополнительных гостей.

## Решения, которые будут зафиксированы в спецификации

Пока не выбраны, это тема следующего шага:

- начало окна: сегодня или завтра;
- часы работы владельца и часовой пояс;
- шаг доступных стартов слотов (например, каждые 30 минут).

## Требования к реализации

- Контракт API описывается на TypeSpec, из него генерируется OpenAPI-спецификация.
- Для фронтенда генерируется клиентский SDK из OpenAPI.
- Приложение собирается в Docker-образ и запускается в контейнере.
- Разработка ведётся с помощью ИИ-агента.

## Хранение данных

> Заполнить после выбора стека: данные в памяти процесса (перезапуск сбрасывает все записи) или база данных.
